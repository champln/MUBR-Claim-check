# MUBR Claim Pre-screen System
**ระบบ Pre-screen ข้อมูลส่งเบิกค่ารักษาพยาบาล**  
ศูนย์การแพทย์มหิดลบำรุงรักษ์ จังหวัดนครสวรรค์

---

## Tech Stack
- **Frontend**: React 18 + TypeScript + Vite + Tailwind CSS
- **Backend**: FastAPI (Python) + SQLite (SQLAlchemy)
- **Charts**: Recharts
- **File Import**: pandas (Excel/CSV)

## การติดตั้ง (Installation)

### Prerequisites
- Node.js >= 18
- Python >= 3.9

### Backend
```bash
cd backend
python -m venv venv
.\venv\Scripts\pip install -r requirements.txt
.\venv\Scripts\pip install numpy pytz python-dateutil pydantic-core==2.18.2
```

### Frontend
```bash
cd frontend
npm install
```

## การเริ่มใช้งาน (Start)

```powershell
# เริ่มทั้งสอง service พร้อมกัน
.\start.ps1
```

หรือเริ่มแยกกัน:
```powershell
# Backend (Terminal 1)
cd backend ; .\venv\Scripts\uvicorn main:app --reload --port 8090

# Frontend (Terminal 2)
cd frontend ; npm run dev
```

เปิด: http://localhost:5173

## การใช้งานจริง (ผู้ใช้ในโรงพยาบาล)

ระบบให้บริการที่ **http://10.49.52.55:8090** (รันเป็น Windows Scheduled Task เริ่มเองเมื่อเปิดเครื่อง)
ในระบบมีเมนู **"วิธีใช้งาน"** อธิบายทุกเมนูพร้อมขั้นตอนและปัญหาที่พบบ่อย — เอกสารนี้เป็นฉบับย่อ

### หลักการที่ทุกเมนูใช้เหมือนกัน
- **ตรวจก่อนแก้เสมอ** ทุกเมนูมีปุ่มดูผลก่อนว่าจะแก้แถวไหน จากค่าอะไรเป็นอะไร
- **แก้เฉพาะช่องที่ตั้งใจ** ไบต์อื่นคงเดิมทุกตัว (ภาษาไทย windows-874, CRLF, ลำดับฟิลด์)
- **เซ็นไฟล์ใหม่อัตโนมัติ** ผู้ป่วยนอกใช้ `Checksum` (MD5 ของทุกไบต์ก่อน `<?EndNote`) ผู้ป่วยในใช้ `HMAC` (MD5 ของไฟล์ที่ตัดบรรทัด `<?xml` และ `<?EndNote` ออก)
- **คืนไฟล์ชื่อเดิม** อัปโหลด .zip ทั้งชุดได้ ระบบแก้เฉพาะแฟ้มที่เกี่ยว แฟ้มอื่นไม่ถูกแตะ

> อย่าแก้ไฟล์ส่งเบิกด้วย Notepad — แก้แล้วไม่เซ็นใหม่จะถูก สกส. ตีกลับ (ผู้ป่วยใน = รหัสปฏิเสธ 22)

### ติด C รหัสไหน ใช้เมนูไหน

| รหัส | ความหมาย | เมนู |
|------|----------|------|
| S19 | รหัสการให้บริการไม่ถูกต้อง/ไม่สัมพันธ์กับ CodeSet | แก้รหัสหัตถการ (S19/S41) |
| S41 | Class เป็นหัตถการ (OP) แต่ไม่แจ้งรหัสที่ STDCode | แก้รหัสหัตถการ (S19/S41) |
| A04 | ยอดหัวบิลไม่ตรงกับผลรวมรายการ | แก้ยอดค่าบริการ (A04/T33/45) |
| T33 / T45 | ค่าบริการทั่วไป ผป.นอก มียอดเบิกเป็น 0.00 | แก้ยอดค่าบริการ (A04/T33/45) |
| T42 | SVDATE ไม่สัมพันธ์กับ BILLTRAN | แก้วันที่ให้บริการ (T42) |
| 22 | ค่า HMAC ท้ายไฟล์ผู้ป่วยในไม่ตรงกับเนื้อไฟล์ | แก้ DateRev ผู้ป่วยใน |

### เมนูแก้ไฟล์ทั้งหมด

| เมนู | ใช้เมื่อ |
|------|---------|
| ตรวจไฟล์ส่งเบิก | ตรวจทั้งชุดก่อนส่ง และแก้ได้ทุกฟิลด์ทีละช่อง (แบบตาราง) |
| แก้รหัสหัตถการ (S19/S41) | STDCode ใน OPServices ว่างหรือไม่ตรง — มีคลังรหัสให้เก็บไว้ใช้ซ้ำ |
| แก้ยอดค่าบริการ (A04/T33/45) | เติมยอดเบิกที่เป็น 0.00 และปรับยอดหัวบิลให้ตรงผลรวมรายการ |
| แก้วันที่ให้บริการ (T42) | วันที่รายการไม่ตรงวัน visit — ระบบหาวันที่ถูกต้องเอง |
| แก้ DateRev ผู้ป่วยใน | DateRev เป็นวันที่ export แทนวันที่จริง + ปุ่มหาค่า HMAC ใหม่ |
| เติมข้อมูล ปกส.รามา SH50 | เติมรหัส รพ.หลักและผู้ร่วมจ่าย 50 บาท |
| แก้ไขรหัส TMT ยา | เปลี่ยนรหัส TMT ให้ตรงกันทั้ง BILLTRAN และ BILLDISP |
| แก้ไฟล์ COVID-19 | เติมรหัสอนุมัติ COV-19 |
| แก้ไฟล์ CPAP/PSG | เติมรหัสอนุมัติและแก้ Class/SvPID |

### รูปแบบไฟล์ที่รองรับ

| ตระกูล | แฟ้ม | แก้ไขได้ |
|--------|------|----------|
| สกส./ข้าราชการ OPD (CHI) | BILLTRAN, BILLDISP, OPServices | ได้ |
| ผู้ป่วยใน | CIPN / AIPN (.xml) | ได้ |
| อปท. e-Claim (LGO) | IDX, CHT, ADP, CHA, DRU | อ่าน/ตรวจได้ |

## การดูแลระบบ (ผู้ดูแล)

```powershell
schtasks /Run   /TN "MUBR Claim Service"            # เริ่มบริการ
schtasks /End   /TN "MUBR Claim Service"            # หยุด
schtasks /Query /TN "MUBR Claim Service" /FO LIST   # ดูสถานะ
```

- บริการฟื้นเองภายใน 2 นาทีถ้า process ตาย (trigger ซ้ำ + MultipleInstances=IgnoreNew)
- สำรองฐานข้อมูลอัตโนมัติทุกวัน 23:00 เก็บย้อนหลัง 30 วันใน `backups/` (task ชื่อ "MUBR Claim DB Backup")
- ความลับของระบบ (JWT secret ฯลฯ) อยู่ใน `backend/.env` ซึ่งไม่ขึ้น git — ดูตัวอย่างที่ `backend/.env.example`
- ไฟล์ `.ps1` ทุกไฟล์ต้องเซฟเป็น **UTF-8 with BOM** ไม่งั้น PowerShell 5.1 อ่านคอมเมนต์ภาษาไทยผิดแล้วสคริปต์พัง

## กฎการตรวจสอบมาตรฐาน

- **DOC**: ความครบถ้วน HN, PID (checksum), วันที่, สิทธิ์
- **ICD**: รูปแบบรหัส ICD-10 (PDX, ADX), ICD-9 (หัตถการ)
- **C_FLAG**: ตรวจสอบรหัสที่ทำให้ติด C Flag
- **DATE**: วันรักษา, วันจำหน่าย, LOS (IPD)
- **AMOUNT**: ยอดเบิก ≤ ยอดรวม, Sub-total check
- **DRG**: รหัส DRG + RW สำหรับ IPD
- **RIGHTS**: เลขสมาชิก SSO / CSMBS
